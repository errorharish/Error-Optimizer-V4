- Page modules are code-split in `pageMap.tsx` (React.lazy, warmed on idle after Shell mounts) and `$page.tsx` keys each page's Suspense by slug. Why: small first launch, instant later navigation, fresh state per page.
- Lightweight Rendering (`settings.lightweight` → `<html data-eo-lite>`) only removes backdrop blur and entrance animations in the styles.css "Lightweight rendering" block; it never touches status indicators, colours or score updates. Why: low-end PCs stay smooth without changing the look.
- The V3 Dashboard first row is one `.eo-dash-hero` grid of equal `minmax(0,1fr)` columns (Score, Auto Optimize, Temperature Monitoring); Auto Optimize and Temperature share the `.eo-card-head` header (status pills under the title, no separate status row), and sizes/breakpoints are mirrored by the startup skeleton's `.eob-hero` in `startup.ts`. System Overview cards are `HwMetric` / `.eo-hwm` (5 → 3 → 2 → 1 columns by content width) on the shared chart tokens. Why: equal compact cards, one header pattern, and a skeleton that matches the real layout.
- `TemperatureCard.tsx` draws its graph with the System Performance Telemetry chart classes (`.eo-chart`, `.eo-morph`, `.eo-chart-area`, `.eo-tele-*`, `.eo-legend-dot`) in a memoised chart that is fed a held snapshot while paused, off-screen or hidden; its series colours are a fixed palette in styles.css, not theme tokens (`temp-series-lock.test.ts`). Why: one chart system, no redraws when nobody is watching, and series stay recognisable in every theme.
- Floating layers use the one `--z-*` scale in styles.css `:root` (sticky < float < modal < popover < tooltip < toast) and render in a `<body>` portal; status details tooltips are portaled by `StatusIndicator` and placed by `placeFloating` (`src/lib/eo/floatingPlacement.ts`). Why: no card overflow, transform or stacking context can clip or cover a tooltip.
- The startup skeleton has one static layout per first-route kind (V3 Dashboard, V4 Dashboard, Settings, standard page) plus V3/V4 docks built from the page registry; `BOOT_ROUTE_FN` in `startup.ts` tags `<html data-eo-boot-view/-suite>` before first paint and CSS shows only the match. Why: the skeleton matches the page actually opening without any JS on the critical path.
- `AnimatedNumber` (controls.tsx) tweens by writing its own text node in one rAF loop and never calls setState per frame; reduced motion and hidden windows jump to the value. Why: live telemetry numbers stay smooth without re-rendering cards on low-end PCs.
